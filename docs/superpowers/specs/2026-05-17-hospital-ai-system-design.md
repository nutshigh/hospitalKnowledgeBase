# 医院AI体检报告识别健康管理系统 — 架构设计

## 概述

面向多家医院的 AI 体检报告识别与健康管理系统。系统分为用户端（体检者）和医生端（体检科/医生），用户端侧重上传报告和查看 AI 解读结果，医生端侧重审核解读、知识库管理和数据分析。

---

## 技术栈

| 类别 | 选型 |
|------|------|
| 后端语言 | Python |
| Web 框架 | FastAPI |
| 前端框架 | React |
| 前端 UI 库 | Ant Design |
| 关系型数据库 | MySQL |
| 向量数据库 | Milvus |
| 消息队列 | RabbitMQ |
| 大语言模型 | 本地私有化部署（vLLM + 开源模型） |
| API 网关 | APISIX |

│  ┌──────────┬──────────┬──────────┬──────────┐    │

│           业务数据库  │  向量数据库  │  缓存           │

### 各层职责

| 层 | 职责 |
|----|------|
| 接入层 | 医生端 / 用户端 / 管理后台三套前端，各自独立部署 |
| API 网关 | 统一认证鉴权、按医院 ID 做数据隔离、路由分发到业务模块 |
| 业务模块层 | 5 个模块各自负责一块业务，通过接口互相调用、通过消息队列异步解耦 |
| 基础设施层 | 文件存储、消息队列、向量检索、LLM 调用——各模块不直接操作，通过基础设施层统一封装 |
| 数据层 | 业务库（按医院做数据隔离）+ 向量库 + 缓存 |

## 2. 模块边界与职责

### 2.1 知识库模块

| 要点 | 说明 |
|------|------|
| 核心职责 | 医疗知识条目的 CRUD、批量导入（结构化/非结构化文档）、知识分类管理 |
| 对外接口 | 提供知识检索接口供「AI解读模块」调用，返回相关医学知识上下文 |
| 内部持有 | 文档解析引擎、向量化流水线、向量索引管理、知识更新触发机制 |
| 不负责 | 不处理用户报告、不做 AI 推理——只管知识的存取和检索 |

### 2.2 报告解析模块

| 要点 | 说明 |
|------|------|
| 核心职责 | 接收用户上传的报告文件，调用 OCR/VLM 完成信息提取，输出结构化数据 |
| 对外接口 | 接收文件 → 返回结构化报告 JSON（含个人信息、检验项目、结果值、单位、参考区间） |
| 内部持有 | 图像预处理、多格式解析、术语标准化映射、异步任务状态机 |
| 不负责 | 不做医学判断、不生成健康建议——只管提取和结构化 |

### 2.3 AI 解读模块

| 要点 | 说明 |
|------|------|
| 核心职责 | 接收结构化报告数据 → 调用知识库检索 → LLM 研判 → 输出解读结果 + 三色分级 |
| 对外接口 | 接收结构化报告 → 返回解读结果（指标正常/偏高/偏低/危急值 + 红/黄/绿标签） |
| 内部持有 | 指标研判引擎、三色规则引擎、高风险人群汇总逻辑、历年对比逻辑 |
| 不负责 | 不直接操作知识库存储、不做报告 OCR——依赖「知识库模块」和「报告解析模块」 |

### 2.4 统计分析模块

| 要点 | 说明 |
|------|------|
| 核心职责 | 基于解读后的结构化数据做多维度统计、趋势分析、报表生成 |
| 对外接口 | 提供统计查询 API、报表导出接口、BI 看板数据接口 |
| 内部持有 | 统计计算引擎、报表模板引擎、图表数据聚合 |
| 不负责 | 不做报告解析、不做 AI 解读——只消费已有数据做分析展示 |

### 2.5 调度管理模块

| 要点 | 说明 |
|------|------|
| 核心职责 | 管理 AI 推理任务的并发数、优先级、资源分配；系统资源监控 |
| 对外接口 | 任务提交接口、并发调整接口、系统资源查询接口 |
| 内部持有 | 任务队列、优先级调度器、资源监控采集器、重试机制 |
| 不负责 | 不做具体业务逻辑——只管任务排队和资源分配 |

### 模块间核心数据流

```
用户上传报告 → [报告解析模块] → 结构化数据 → [AI解读模块]
                                                    ↓ 查知识
                                              [知识库模块]
                                                    ↓ 返回上下文
                                              [AI解读模块]
                                                    ↓ 输出解读 + 分级
                                              写入业务库
                                                    ↓
用户查看解读 ←──────────── 读取业务库 ←─────── [统计分析模块] 消费数据生成报表
```

## 3. 多医院数据隔离

### 3.1 业务数据库隔离

采用**数据库级隔离**：每家医院独立数据库。各医院数据完全独立，备份恢复独立，满足医疗合规要求。跨院统计通过统计分析模块从各库读取后聚合。

### 3.2 向量数据隔离

采用**命名空间隔离**：同一向量库实例内，每家医院独立命名空间（Namespace/Collection）。检索时天然隔离，不依赖代码层面过滤。

如后续有「公共医学知识库」需求（全国通用诊疗标准等），在命名空间之外加一个共享命名空间，AI 解读时并行检索医院命名空间 + 公共命名空间，合并结果。

## 4. 异步任务架构

```
用户上传报告
     ↓
[报告解析模块] 接收文件，创建任务
     ↓
消息队列（任务排队）
     ↓
Worker 消费者：图像预处理 → OCR/VLM 解析 → 结构化存储
     ↓
解析完成后 → 发布"解析完成"事件
     ↓
[AI解读模块] 消费事件 → 拉取结构化数据 → 知识库检索 → LLM 研判
     ↓
解读完成 → 写结果库 → 推送通知给用户
```

| 要点 | 说明 |
|------|------|
| 解析和解读串行 | 解析成功后才触发解读，避免空数据进 LLM |
| 状态机 | 每个报告有生命周期：排队中 → 解析中 → 解读中 → 完成 / 失败 |
| 失败重试 | 解析或解读失败可自动重试，超过次数标记为"解析失败"或"解读失败" |
| 优先级 | 紧急报告可优先入队，由调度管理模块控制 |
| 解耦方式 | 报告解析模块和 AI 解读模块之间通过事件驱动，不直接调用 |

## 5. 三色预警规则引擎

### 规则引擎流程

```
结构化报告数据
       ↓
  指标逐项进入规则引擎
       ↓
┌─────────────────────────────────────────────┐
│              规则引擎                          │
│                                              │
│  规则类型：                                    │
│  1. 数值范围规则：结果值 vs 参考区间             │
│     → 在区间内=绿，轻度偏离=黄，显著偏离=红       │
│     → 危急值（如血糖>33.3）=强制红              │
│  2. 关键指标规则：特定指标（肿瘤标志物等）         │
│     异常值直接红                                │
│  3. 组合规则：多指标联合判断                     │
│     如：ALT+AST 同时显著超标 = 红               │
│  4. 趋势规则：同一指标历年持续恶化 = 黄/红        │
└─────────────────────────────────────────────┘
       ↓
   输出：每项指标标签（红/黄/绿）+ 解读文字
       ↓
   汇总：报告整体评级 + 红区指标汇总清单
```

### 规则引擎与 LLM 分工

| 环节 | 负责方 | 原因 |
|------|--------|------|
| 正常/偏高/偏低/危急值判定 | 规则引擎 | 确定性逻辑，不需要 LLM |
| 红/黄/绿标签 | 规则引擎 | 可配置、可审计、可解释 |
| 解读文字 + 健康建议 | LLM + RAG | 需要自然语言生成和医学知识支撑 |
| 复查建议 / 干预措施 | LLM + RAG | 需要结合具体异常项和知识库 |

### 规则管理

- 医生端管理员可在后台修改阈值、新增/禁用规则
- 规则存储于业务库，每家医院可有自己的规则集
- 执行顺序：先数值范围 → 再关键指标 → 最后组合和趋势。命中危急值快速路径直接标红

## 6. RAG 知识入库与检索流水线

### 知识入库流程

```
医疗文档/指南/指标表/临床路径
        ↓
  ┌──────────────┐
  │  文档解析引擎   │  ← 支持 PDF/Word/Excel/文本
  └──────────────┘
        ↓
  ┌──────────────┐
  │  文本分段器    │  ← 按章节/段落/题目切分，保留文档结构
  └──────────────┘
        ↓
  ┌──────────────┐
  │  向量化引擎    │  ← Embedding 模型生成向量
  └──────────────┘
        ↓
  ┌──────────────┐
  │  向量库存储    │  ← 写入对应医院命名空间，附带元数据（来源、分类、更新时间）
  └──────────────┘
```

### 检索流程（AI 解读时调用）

```
结构化报告数据（指标名+值）
        ↓
  ┌──────────────┐
  │  检索 Query   │  ← 将异常指标拼接为检索语句
  │  构造器       │
  └──────────────┘
        ↓
  ┌──────────────┐
  │  向量检索     │  ← 在对应医院命名空间做语义检索
  └──────────────┘
        ↓
  ┌──────────────┐
  │  结果排序     │  ← 按相关度排序，Top-K 截断
  └──────────────┘
        ↓
  ┌──────────────┐
  │  上下文组装   │  ← 检索结果 + 原始报告 → Prompt 上下文
  └──────────────┘
        ↓
     送入 LLM 生成解读
```

### 知识更新机制

| 场景 | 方式 |
|------|------|
| 新增一条知识 | 单条向量化 → 追加写入命名空间 |
| 修改一条知识 | 删除旧向量 → 生成新向量 → 写入 |
| 批量导入新文档 | 全文解析 → 分段 → 向量化 → 批量写入 |
| 删除知识 | 通过元数据定位 → 删除对应向量 |
| 局部重建索引 | 仅重建受影响的知识分类，无需全量重建，系统不中断 |

## 8. 认证与权限体系

### 角色定义

| 角色 | 所属端 | 数据范围 | 权限范围 |
|------|--------|----------|----------|
| 体检者/用户 | 用户端 | 只看自己的报告 | 上传报告、查看解读、个人中心 |
| 医生 | 医生端 | 看所属医院的全部数据 | 报告管理、审核、知识库管理、规则配置、统计分析、系统配置——医生端所有功能 |
| 平台超管 | 管理后台 | 跨院数据 | 租户管理、系统监控、运营配置 |

### 数据隔离模型

```
请求 → API 网关
         ↓
    身份认证（JWT Token）
         ↓
    提取角色 + 医院 ID
         ↓
    ┌──────────────────────┐
    │  数据权限过滤器        │
    │  - 用户端：强制绑定 user_id
    │  - 医生端：强制绑定 hospital_id
    │  - 管理后台：跨院或单院可选
    └──────────────────────┘
         ↓
      业务模块（不再感知权限）
```

- 三端共用同一认证服务，JWT Token 内包含 user_id、角色、hospital_id
- API 网关校验 Token 后，将 identity 注入请求上下文，模块层直接信任
- 用户上传报告时，user_id 从 Token 提取，报告与用户强绑定

## 9. 文件存储方案

### 存储结构

```
文件存储
├── hospital_A/
│   ├── reports/
│   │   ├── 2025/
│   │   │   ├── user_123/
│   │   │   │   ├── 20250517_report_001.pdf
│   │   │   │   └── 20250517_report_001_thumb.jpg
│   │   │   └── ...
│   │   └── 2026/
│   └── knowledge/
│       └── ...
├── hospital_B/
│   └── ...
```

| 要点 | 说明 |
|------|------|
| 按医院隔离 | 每家医院独立目录，与数据库隔离方案一致 |
| 按年月分层 | 避免单目录文件过多，便于归档 |
| 文件生命周期 | 上传 → 解析完成 → 归档；解析失败文件保留 30 天清理 |
| 缩略图 | 报告图片生成缩略图，用于列表页展示 |
| 访问控制 | 不对外暴露直链，通过 API 鉴权后代理下载 |
| 多格式支持 | PDF、Word、JPG/PNG 均按原格式存储 |

## 10. 错误处理策略

| 场景 | 处理方式 |
|------|----------|
| 报告文件格式不支持 | 上传时前端校验 + 后端二次校验，返回明确错误提示 |
| 图像质量不合格（模糊/倾斜） | 前端预处理检测，提示用户重新拍摄 |
| OCR/VLM 解析超时 | 任务超时自动标记"解析失败"，通知用户重新上传 |
| LLM 调用超时/配额耗尽 | 任务进入重试队列，超过重试次数后标记失败并告警 |
| 知识库检索无结果 | LLM 仅基于报告数据生成解读，同时记录"知识缺失"日志供后续补充 |
| 消息队列堆积 | 调度管理模块监控队列深度，超阈值自动扩容或限流 |
| 医院数据库连接失败 | 仅影响该医院，其他医院正常服务；触发告警 |
